# Wearable light logger inventory

A literature directory from the **Translational Sensory & Circadian Neuroscience Unit (MPS/TUM/TUMCREATE)**.

Website: https://resources.tscnlab.org/lightloggers/

## Rebuild

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
QUARTO_PYTHON=.venv/bin/python quarto render
```

Quarto executes `index.qmd`, `evidence.qmd` and `source.qmd` using the versioned records in `data/library.json`. It writes the directory to `_site/lightloggers/`. The post-render script adds the resources landing page at `_site/index.html`.

Serve `_site` with a static server to preview the full URL structure. All links, styles, data downloads and journal logos work under `/lightloggers/`.

## Publish

GitHub Actions renders the Quarto project, checks the filtering logic and publishes `_site` to GitHub Pages. Set the repository's custom domain to `resources.tscnlab.org`. In DNS, `resources` is a CNAME pointing to `tscnlab.github.io`.

The original `lightloggers.tscnlab.org` address forwards to `https://resources.tscnlab.org/lightloggers/`, with requested paths included. This forwarding is managed in Porkbun.

## Update the directory

Edit `data/library.json` and re-render. Device outputs and examined measurements are stored separately. The combined metric columns cover photopic illuminance and melanopic EDI. Properties cover accuracy, measurement range and angle dependence. Comparisons during wear and within/between units are included. The interface groups devices by manufacturer and can sort by validation count or device name.

The submission form prepares email to the address in `site-config.json`. Suggested papers are reviewed before inclusion.

## Social preview

Open Graph and large-image Twitter Card tags are generated by Quarto. The artwork follows the Join website template, with the light logger title and URL. To regenerate the checked-in PNG:

```sh
node scripts/render-social-preview.cjs
```

This optional artwork step needs Playwright and Chrome. Normal site builds use the existing PNG. Asset sources are recorded in `assets/PROVENANCE.md`.

## Verification and downloads

```sh
node --test tests/*.test.cjs
node tests/browser.cjs
python scripts/package.py
```

Browser checks use Playwright and Chrome; `PLAYWRIGHT_MODULE`, `CHROME_PATH` and `BASE_URL` can override their defaults. Screenshots and the browser report are written to `preview/`. The package contains the Quarto source, rendered HTML, data and assets.

The directory offers CSV and BibTeX downloads. Search records and extraction notes remain in `data/` so the literature inventory can be maintained reproducibly.

## Source reader

`data/source-evidence.json` maps claims, device models and measurements to short quotations, section links and PDF coordinates. Each coordinate is tied to the SHA-256 of the inspected PDF edition. The reader renders an unchanged original PDF with a separate highlight overlay; another edition is shown without those highlights. Local files stay in the browser.

The inventory and About page open the reader in a modal iframe, preserving the current search and scroll position. It has page navigation, zoom and passage selection, with no download or print controls. Hosted PDFs load automatically from this repository. Public static PDF URLs remain accessible independently of the viewer.

The reader uses the vendored Mozilla PDF.js distribution. Normal Quarto builds need no PDF extraction software or network access. To index a newly selected passage, install PyMuPDF and use `scripts/index-source-pdf.py`; inspect the rendered highlight before committing it. Keep abstract-only locators labelled and never infer missing page numbers.

All 28 indexed papers have PDFs under `sources/`. Authors, original URLs, available reuse terms and the provenance of files supplied by the site owner are recorded in the source manifest and `sources/README.md`. Owner-supplied files retain their original copyright notices; their inclusion does not assert a new reuse licence. PDF.js is Apache-2.0, version recorded in `assets/vendor/pdfjs/VERSION`.

## ENLIGHT wizard

The `enlight/` directory is an independent Quarto project published at
<https://resources.tscnlab.org/enlight/>. Its data, browser code and reproducible
source are kept separate from the light logger inventory.

To rebuild both resources locally:

```sh
quarto render
python scripts/build-enlight.py
```

The integration script renders ENLIGHT and copies its output into `_site/enlight/`
after the root project has rendered `_site/lightloggers/`. The existing GitHub
Pages workflow publishes the combined `_site/` directory. No DNS changes are
needed. See `enlight/README.md` for the checklist provenance and PDF export checks.
